## 1. 装扮套装（suit）到底是什么

B站一套「装扮」不是一张图，而是一个**套装**。服务端 `x/garb/v2/mall/suit/detail`
（`item_id=` 装扮 id）的响应里，`data.suit_items` 是套装的**组件清单**。

对 `bz7058/bilibili-skin` 仓库里 12 套真实套装取样，`suit_items` 的键**并集**为：

```
card         动态卡片
card_bg      专属评论装扮
emoji_package 表情包
loading      专属加载动画
play_icon    专属进度条
skin         专属个性主题
space_bg     专属空间海报
thumbup      动态点赞特效
```

每个键是**数组**，元素结构统一：

```jsonc
{
  "item_id": 46076,          // 子项 id
  "name": "2023拜年纪",
  "state": "active",
  "suit_item_id": 46075,     // 所属套装 id
  "properties": { /* 各组件的差异都在这里 */ }
}
```

各组件 `properties` 的关键字段（取自真实数据）：

| 组件 | 关键字段 |
|---|---|
| `skin` | `package_url` `package_md5` `ver` `color` `color_mode` `color_second_page` `side_bg_color` `tail_color` `tail_color_selected` `tail_icon_ani` `tail_icon_ani_mode` `tail_icon_mode` `tail_icon_*`（各底栏图标）`head_bg` `head_tab_bg` `head_myself_*` `tail_bg` `image_cover` `image_preview` `skin_mode` |
| `loading` | **`loading_url`**（加载动画图）`loading_frame_url`（其中一帧）`ver` `image_preview_small` |
| `card` | `image` `image_preview_small` `sale_type` |
| `card_bg` | `image` `image_preview_small` |
| `thumbup` | `image_ani` `image_ani_cut` `image_preview` |
| `play_icon` | `drag_left_png` `drag_right_png` `middle_png` `squared_image` `static_icon_image` |
| `space_bg` | `image1_landscape` … `image7_portrait` `fan_no_color` `fan_no_image` |
| `emoji_package` | `image` `item_ids` `preview` `biz` `size` |

> **旧版模块的根因**：只读了 `suit_items.skin`，其它七个组件从候选里就被丢掉了。
> 现在 `equipFrom()` 会把整份 `suit_items` 收进 `equip.components`，按类型分别注入。

## 2. 逐类型：来源 / 接口 / 注入位置

### 2.1 个性主题 `skin` —— `data.user_equip`

* **来源**：`suit_items.skin[0].properties`（`package_url` 是一个 zip，内含 `head_bg.jpg`、
  `tail_icon_*.png` 等 17 张图）
* **接口**：`GET api.bilibili.com/x/garb/v2/mall/suit/detail?item_id=<装扮id>&part=suit`
* **注入位置**：`app.bilibili.com/x/resource/show/skin` 响应 → `data.user_equip`

```jsonc
// x/resource/show/skin 响应
{
  "code": 0,
  "data": {
    "user_equip": { "id": 2529, "name": "初音未来-日版", "preview": "...", "ver": 1598600025,
                    "package_url": "https://i0.hdslb.com/bfs/garb/zip/....zip",
                    "package_md5": "7b6d...", "data": { "color_mode": "light", "color": "#212121", ... } },
    "skin_colors": [ { "id": 2, "name": "少女粉", "is_free": true }, ... ],
    "load_equip":  { "id": 2531, "name": "初音未来13周年", "ver": 1598602035,
                     "loading_url": "https://i0.hdslb.com/bfs/garb/item/....webp" }
  }
}
```

**调整方式**：整段替换 `data.user_equip`，`data.skin_colors` 原样保留（它是免费配色表）。

### 2.2 加载动画 `loading` —— `data.load_equip` ★ 关键修复

加载动画**不是**独立接口，它就在**同一个 skin 响应**里，字段是 `data.load_equip`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | num | 装扮 id |
| `name` | str | 名称 |
| `ver` | num | 版本（时间戳） |
| `loading_url` | str | 加载动画图（webp） |

* **来源**：`suit_items.loading[0].properties.loading_url`（+ `loading_frame_url`）
* **接口**：同上，`x/garb/v2/mall/suit/detail`
* **注入位置**：`x/resource/show/skin` → **`data.load_equip`**

```jsonc
// 注入后
"load_equip": {
  "id": 46076,
  "name": "2023拜年纪",
  "ver": 1673689428,
  "loading_url": "https://i0.hdslb.com/bfs/garb/item/xxx.webp"
}
```

**为什么以前拿不到**：旧代码只写 `data.user_equip`，完全没碰 `data.load_equip`，
所以无论选哪套，加载动画永远是账号原来的。现在 `handleApply()` 在同一个响应里
**同时**写 `user_equip` 和 `load_equip`。

> 实现细节：App 侧的 `BFCPullToRefreshHeaderView` 从
> `com.bilibili.PullToRefreshResouce` 配置里读 `load_equip` / `loading_url`；
> 这个配置就是由 `x/resource/show/skin` 的 `data.load_equip` 喂的。

### 2.3 动态卡片 `card` / 评论装扮 `card_bg` —— `member.user_sailing_v2.card_bg`

B站把「你的卡片」放进**评论 / 动态响应里的 member 节点**。IPA 二进制里能直接读到
这几条 KVC 键路径：

```
member.user_sailing.pendant
member.user_sailing.pendant.image
member.user_sailing_v2.card_bg
```

* **来源**：`suit_items.card[0].properties.image`（动态卡片）、
  `suit_items.card_bg[0].properties.image`（评论装扮）
* **接口（取）**：`x/garb/v2/mall/suit/detail`
* **注入位置**：评论 / 动态响应 → `data.replies[].member.user_sailing_v2.card_bg`、
  `...user_sailing.card_bg`（对象或字符串都兼容）

IPA 里对应的模型（`bilibili.vas.garb.model`，protobuf）：

```proto
message UserCardBG {          // card_bg
  int64  id = 1;  string name = 2;  string image = 3;
  string jump_url = 4;  UserFanShow fan = 5;
  string type = 6;  ImageGroup image_group = 7;
}
message UserSailing {         // 账号当前装备
  UserPendant pendant = 1;  UserCardBG card_bg = 2;  UserCardBG card_bg_with_focus = 3;
}
message UserPendant { int64 id=1; string name=2; string image=3; string image_enhance=6; }
```

**调整方式**：`handleCard()` 递归遍历响应，**只改 `member.mid == 自己 mid` 的节点**
（`selfMid` 由 H5 页面通过 `x/web-interface/nav` 拿到后经桥上报）。
保留原对象结构，只替换 `image` / `id` / `name`。别人的 member 一律不动，避免全站串味。

> **注意**：这套卡片同时被 gRPC 服务 `bilibili.vas.garb.service` 下发
> （`SailingEquipMulti` → `map<mid, UserSailing>`，`UserCardMulti` → `map<mid, UserCard>`）。
> 走 gRPC 的那条路径 Surge 改不了，能改的是 HTTP JSON 里的 member 节点（评论 / 动态流）。

### 2.4 点赞特效 / 进度条 / 空间海报 / 表情包

| 组件 | 来源 | 注入位置 |
|---|---|---|
| `thumbup` | `suit_items.thumbup[0].properties.image_ani` | 点赞动画由 `BAPIVasGarbModel` 服务端下发，客户端不缓存 → **不可注入** |
| `play_icon` | `suit_items.play_icon[0].properties.*` | 播放器进度条，同上 → **不可注入** |
| `space_bg` | `suit_items.space_bg[0].properties.image*` | 个人空间海报，走 `x/v2/space/garb/detail` 服务端装备态 → 客户端改不了 |
| `emoji_package` | `suit_items.emoji_package[0].properties.*` | 表情包要服务端「拥有」才能发 → **不可注入** |

这四类的**数据能抓到**（收进 `equip.components`，卡片上带角标），但**渲染**依赖服务端
下发的装备态或 gRPC，纯客户端改写做不到。硬要做的唯一路子是本地替换资源文件，
那属于改 App 本体，不在本模块范围。

### 2.5 抽奖主题 / 收藏集

收藏集（数字藏品 / 抽卡）和装扮是**两套 id 体系**，但收藏集的「主题套装」本身就是一套普通装扮。
关键在收藏集详情里的 `collect_infos`：

* **接口**：`GET api.bilibili.com/x/vas/dlc_act/lottery_home_detail?act_id=<活动id>&lottery_id=<抽奖id>`
  （`lottery_id` 缺了不返回数据）
* **结构**（两种，代码都兼容）：

```jsonc
// 新版（lottery_home_detail）
"data": { "collect_list": { "collect_infos": [
  { "collect_id": 123, "redeem_item_type": 4, "redeem_item_id": "37670",
    "redeem_item_name": "灵魂潮汐", "redeem_item_image": "https://...",
    "jump_url": "...", "remain_stock": 5, "total_stock": 100 }
] } }

// 旧版（lottery/home_detail/v2）：data.collect_list 直接是数组
```

`redeem_item_type`：**4 = Suit（主题套装，`redeem_item_id` 就是装扮 id）**，
5 = MaterialCombination（动态主题套装，是若干子项 id，用 `&` 连接）。
IPA 里收藏集模型还带 `garb_suit_url` / `garb_apply_url` 两个直链字段。

* **注入位置**：解析出的装扮 id 走 `x/garb/v2/mall/suit/detail` 取详情，
  再按 §2.1 / §2.2 注入 `user_equip` + `load_equip`。

**调整方式**：`collectCandidates()` 现在会读 URL 上的 `act_id` / `lottery_id`，
调 `lottery_home_detail`，用 `mapRedeemIds()` 抽出 type 4/5 的 id 再逐个解析。
`mapRedeemItems()` 还能把兑换物名字 / 预览图 / 跳转链接拿出来做提示。

> 收藏集相关接口全景（IPA 提取）：
> `x/vas/dlc_act/lottery_home_detail`、`x/vas/dlc_act/act/card/detail`、
> `x/vas/dlc_act/card/splash_info`、`x/vas/dlc_act/lottery/draw_item`、
> `x/garb/digital/card/detail`、`x/vas/nftcard/{carddetail,drawcard,isallowtransfer}`。

### 2.6 开屏动画 `splash`

开屏动画**不在** `suit_items` 里（取样 12 套套装都没有 `splash` 组件），它是独立系统。
IPA 里能读到三个不同的开屏通道：

| 通道 | 接口 | 说明 |
|---|---|---|
| 品牌开屏 | `app.bilibili.com/x/v2/splash/brand/list` | `data.{pull_interval,list[],show[]}`，`list[].thumb` 就是开屏图 |
| 活动开屏 | `app.bilibili.com/x/v2/splash/event/list2` | 刮刮卡 / 滑动交互开屏，带 `front_image_url` `back_image_url` 等 |
| Chronos 开屏 | `app.bilibili.com/x/chronos/package/obtain` | 动态组件包，`ObtainChronosPackageReq{service_key,engine_version,biz_id}` → `Rsp{md5,url,sign}` |

IPA 里的类：`BFCChronosSplash`、`BFCChronosPackageDownloader`，
配置键：`chronos.splash_package_url` / `chronos.splash_package_md5` / `chronos.splash_enabled`。

**本次实现的是品牌开屏**（结构最清晰、纯 JSON、Surge 可直接改）：

* **来源**：`x/v2/splash/brand/list` 自身下发的 `data.list[]`
* **注入位置**：同一响应的 `data.list` / `data.show` —— 把选中的开屏图 `unshift` 到最前

```jsonc
// 注入后
"data": {
  "pull_interval": 1800,
  "list": [ { "id": 900000001, "thumb": "<你选的开屏图>", "logo_url": "" }, ...原有 ],
  "show": [ { "id": 900000001, "begin_time": 0, "end_time": 0, "probability": 0, "duration": 3000 } ]
}
```

**调整方式**：`handleSplash()` 一个响应干两件事——① 把服务端下发的开屏图记进
`BiliSkinSplashList` 供 H5 挑选；② 把 `BiliSkinSplash` 里选中的开屏插到 `list/show` 最前。
H5 侧 `mapSplashItems()` 把候选渲染成卡片，应用时走 `/splash/set`。

> 活动开屏（`event/list2`）和 Chronos 开屏结构更复杂（前者是前后卡片 + 交互参数，
> 后者是 gRPC 包），本模块暂未接管，接口已在表里列出，需要时可扩展。

## 3. 为什么以前「只注入了一部分直购主题」

| 现象 | 根因 | 修复 |
|---|---|---|
| 抽奖 / 收藏集主题抓不到 | 收藏集页面只加载卡片数据，模块没去解析 `collect_infos` | 新增 `lottery_home_detail` 解析 + `redeem_item_id` 解析 |

| 动态卡片 / 评论装扮抓不到 | 旧代码不碰评论 / 动态响应 | 新增 `handleCard`，改自己 member 的 `card_bg` |
| 开屏动画抓不到 | 完全没有对应的嗅探与注入规则 | 新增 `x/v2/splash/*` 规则 |
| 其它组件（点赞 / 进度条 / 海报 / 表情） | 只读了 `suit_items.skin` | `equipFrom` 收全部组件（能抓，部分不可注入） |

## 6. 边界与已知限制

1. **gRPC 通道改不了**：动态卡片、点赞特效、进度条等还有一条 gRPC 下发路径
   （`bilibili.vas.garb.service`）。Surge 只能改 HTTP JSON，gRPC 走不了。
2. **评论装扮只改自己**：需要 `selfMid`（H5 页面进过一次就会上报）。拿不到就整体放行，不串味。
3. **开屏只接管品牌开屏**：活动开屏 / Chronos 包未接管。
4. **已下架装扮**：B站不再下发图片包，没有 `package_url` 就无法渲染，仍靠「藏馆」缓存兜底。
5. **仅本地生效**：所有改动都是客户端渲染层面的替换，不同步账号，别人看不到。
