## 6. 已判定不可行

| 项 | 原因 |
|---|---|
| 注入任意 Chronos 包 | 包体有 RSA 签名（`BFCChronosFileValidator` + 硬编码公钥），伪造不了 |
| 表情包 `emoji_package` 注入 | 表情要服务端确认「拥有」才能发，本地替换没意义 |
| 点赞特效 / 播放器进度条 | 客户端二进制里没有对应字段的读取路径（`image_ani` / `thumbup` 都不存在），JSON 改成什么都不生效 |
| 已下架装扮的图片包 | B站不再下发 `package_url`，没图无法渲染；靠藏馆兜底 |
| 让别人看到你的装扮 | 所有改动都是客户端本地的，不同步账号 |
| 从普通装扮拿头像挂件 | `suit_items` 里根本没有 `pendant`（60 套实测）。只能从收藏集兑换物 / 已拥有挂件列表里抓 |
| 强制开屏 | 品牌开屏要 App 主动请求 `brand/list`，活动开屏要 md5 对得上，Chronos 要服务端签名。模块只能「在已有通道上换图 / 回放」 |

## 7. 模块构成

**只有一个模块**：`BiliSkinStudio.sgmodule`，10 条 `[Script]`，全部功能都在里面。

其中两条代价较大，出问题可以单独删掉那一行：

| 规则 | 代价 | 删掉的后果 |
|---|---|---|
| `BiliSkinGrpc`（第 9 条） | 让 Surge 解密 `grpc.biliapi.net` | gRPC 那条路径上的装扮不生效（HTTP 那条仍生效） |
| `BiliSkinCache`（第 10 条） | 让 Surge 解密 B站 CDN | Chronos 包不再本地缓存（回放仍可用） |

`BiliSkinGrpc` 的 pattern 已经窄到只圈 `garb` 相关方法，其它 gRPC 流量（信息流 / 播放器 / 直播）不碰。

### 改 pattern 时的三条铁律

1. **pattern 必须真能命中**。少一个 `/`、多一个 `\/` 都会让整条规则静默失效
   （2026-10 就踩过：`splash\/` 写成 `splash\//`，开屏整条规则一次都没触发过）。
2. **pattern 放宽了，`main()` 里的分派必须同步**。Surge 对同一请求只跑第一条
   命中的 `[Script]`，分派全靠 `main()` 里的 URL 判断；规则命中但分派没跟上的话，
   请求会掉进 `handleCandidates` 把 HTML 当 JSON 解析，一样静默失效
   （2026-10 踩过：注入规则放宽到 `/h5/garb/*`，`INJECT_RE` 没改，抽卡页按钮一直不出现）。
3. **pattern 能碰的主机必须进 MITM**。`BiliSkinCache` 的 `.cron` 实际下发在
   `queue.package.bfcchronos.bilibili.com`，只写 `hdslb` / `bilivideo` 的话规则永远不触发。

这三条都由 `scripts/test-bili-module.js` 机械校验，改完跑一遍即可。
桥（第 1 条）的 `timeout` / `max-size` 也有下限要求：`splash/set` 要拉图算 md5（20s）、
`chronos/set` 要拉 `.cron` 包（30s），`import` 要放得下整份导出（藏馆 300 套）。
